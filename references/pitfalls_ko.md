# 주의사항 (직접 확인한 것)

여기에는 모두 실제로 겪은 문제를 적었다. 라우터로 바꾸면서 예전 릴레이, 프록시, 자식 `claude` 워커에만 해당하는 항목은 뺐다. 남은 항목은 지금도 해당하거나 다시 확인한 것들이다.

## 모델 슬러그

**모델 슬러그는 `gpt-daybreak-blue`다(2026-08-19 실측).**
버전 접두사가 있는 `gpt-5.6-daybreak-blue`와 `gpt-5.6-daybreak`는 HTTP 400을 반환한다. 접두사가 없는 슬러그만 200을 반환한다.

**ASTRA의 슬러그는 `gpt-6-astra`다. `version`을 보내지 않으면 통과하지만 오래된 값을 보내면 거부한다.**
`gpt-6`, `gpt-astra`, `gpt-6-astra-latest`는 모두 400을 반환한다(2026-09-05 실측). 이와 별도로 호출자가 오래된 CLI 버전을 명시하면 백엔드는 `The 'gpt-6-astra' model requires a newer version of Codex`로 답한다. 0.144.1은 거부하고 0.153.4는 허용했으므로 예전 프록시는 `version: 0.153.4`를 보냈다. 라우터는 `version` 헤더를 아예 보내지 않으며 이 요청은 통과한다. 2026-09-18에 라우터와 정확히 같은 헤더로 요청해 쿼터 검사까지 진행하는 것을 확인했다. 오래된 값을 보내느니 생략하는 편이 낫다. 다시 측정하지 않고 헤더를 추가하지 않는다.

**쿼터가 없어도 429로 슬러그를 검증할 수 있다.**
모델 검증은 쿼터 검사보다 먼저 한다. 2026-09-18에 같은 인증 정보로 1분 안에 연달아 측정했다. `gpt-6-astra-latest`는 400 `model is not supported`를, `gpt-6-astra`와 `gpt-daybreak-blue`는 429 `usage_limit_reached`를 반환했다. 따라서 429는 슬러그를 받아들였다는 뜻이며, 쿼터를 다 쓴 계정에서도 슬러그를 확인할 수 있다. 이때는 라우터 체크아웃 안에 작은 스크립트를 두고 어댑터의 `readBorrowed`, `toResponsesRequest`, `DEFAULT_BASE`를 가져와 사용했다. 그래야 어댑터와 정확히 같은 요청을 보낸다. 이 스크립트는 배포하지 않는다. 요청을 손으로 구성하지 말고 같은 방식으로 직접 작성한다.

## 라우터의 결함과 수정

2026-09-17에 라우터 소스를 읽고 세 가지를 보고했으며, 모두 이틀 안에 수정했다. 네 번째는 2026-09-19에 직접 겪어 발견했고 다음 날 수정했다.

**긴 도구 이름 문제는 수정했지만 사용 중인 빌드를 확인해야 한다.**
Responses 함수 이름은 `^[a-zA-Z0-9_-]{1,64}$`와 일치해야 한다. 이름 하나라도 조건을 어기면 해당 도구만 실패하는 것이 아니라 요청 전체가 실패한다. Claude Code의 MCP 도구 이름은 `mcp__<server>__<tool>`이다. claude.ai 커넥터의 서버 이름은 UUID이므로 접두사만 43자다. 이제 라우터는 바꿔야 하는 이름을 모두 변환한다. 허용 문자로 정리한 이름의 앞 55자에 `_`와 원래 이름의 sha256 앞 8자리 16진수를 붙이므로 `a.b`와 `a-b`는 충돌하지 않는다. 응답의 `function_call`에서는 원래 이름으로 되돌린다. 이미 조건에 맞는 이름은 그대로 둔다. 따라서 MCP 도구가 없는 세션에서는 출력이 바이트 단위로 같고 캐시 접두사도 바뀌지 않는다. Issue #1은 종료했다. **0.3.0(2026-09-23)에 포함했으며 0.2.0에는 없다.**

**모델별 컨텍스트 윈도우 문제는 수정했다.**
이제 `CliModel.contextWindow`와 `Route.contextWindow`가 전역 `cli.autoCompactWindow`보다 우선한다. 제공자가 보고한 `context_length`는 모델별 설정이 없을 때 쓰며, 전역 설정보다 우선한다. Issue #2는 종료했고 0.3.0에 포함했다.

**`contextWindow`는 압축을 시작하는 토큰 수가 아니다. 그 차이는 고정된 예약량이다.**
2.1.258 바이너리에서 확인한 압축 기준은 `effectiveWindow - 13000`이며, `effectiveWindow = contextWindow - min(maxOutputTokens, 20000)`이다. 비율로 계산하지 않는다. `behavesAs`로 Opus의 출력 상한을 쓰면 예약량은 33,000으로 고정된다. 원하는 토큰 수에서 압축하려면 그 수에 33,000을 더해 적는다. 설정의 533000(Daybreak, 500k에서 압축)과 893000(ASTRA, 860k에서 압축)은 이렇게 정했다. 두 가지 상황에서 이 값이 의도와 달라진다. `behavesAs`를 빼면 미인식 모델의 작은 기본 출력 상한을 쓰므로 예약량이 줄고 압축 기준은 높아진다. 업스트림이 계산식을 바꿔도 두 설정값이 의도한 토큰 수에서 압축하지 않는다. 업스트림의 기록에는 200K 윈도우에서 151K에 압축했다고 되어 있지만, 이 식으로는 167,000이 나온다. 서로 맞지 않으므로 버전이 달라져도 어느 한쪽 수치가 맞으리라 믿지 말고 다시 계산한다.

**서버 측 도구 문제는 수정했다. 실제로 문제가 없었던 이유도 알아둘 만하다.**
Anthropic의 `web_search` 같은 도구는 이를 받은 모델이 직접 실행하지 않고 Anthropic이 실행한다. 따라서 요청 형식을 변환해 다른 제공자에게 보낼 때 이 도구를 선언해도 실행할 수 없다. 이제 두 변환기는 `compat.ts`의 규칙을 재사용해 `type`이 지정되어 있으면서 `custom`이 아닌 도구를 모두 제거한다. 제거한 도구를 가리키는 `tool_choice`도 지운다. Issue #4는 종료했고 0.3.0에 포함했다.

이 변경은 실제 장애를 고친 것이 아니라 앞으로 생길 오류를 막기 위한 것이었다. **Claude Code는 애초에 주 요청에 `web_search`를 넣지 않는다.** WebSearch는 자체 시스템 프롬프트와 서버 도구 사용을 강제한 별도 요청을 만든다. 이 요청은 세션 모델 대신 `tengu_plum_vx3` 플래그로 지정한 소형 모델에 보낸다. 2026-09-17에 업스트림에서 측정했을 때 Opus 세션과 라우팅한 세션의 검색 요청은 바이트 단위로 같았다. 둘 다 Anthropic의 `claude-haiku-4-5`로 직접 보냈다. Issue #4는 종료했다.

**예시로 쓴 표식도 표식으로 처리한다.**
라우터는 처음 다섯 사용자 메시지 어디서든 `[[gpt: ...]]` 형태를 찾았다. 2026-09-19 라우팅 변경 후에는 기존 규칙이 라우팅하는 모델뿐 아니라 모든 모델에 적용했다. 그래서 본문에 문법을 인용해도 지시로 처리했다. 2026-09-19에 이 하네스의 메모에 있던 문자열 때문에 세션의 모든 `claude-sonnet-5`와 `claude-haiku-4-5` 호출을 20분 동안 ASTRA의 max effort로 보냈다. 호출마다 입력은 약 80k 토큰이었다. 자동 모드 분류기는 평소 1초 걸리던 처리가 17~120초로 늘어 시간 초과가 났고, 모든 Bash 호출을 거부했다. 문법을 적을 때는 꺾쇠괄호로 감싼 자리표시자를 쓴다. 표식의 문자 클래스가 이 형태에는 일치하지 않는다. clauderipple#13으로 보고했다. 제공자의 `models` 목록을 비우면 표식이 어느 제공자도 선언하지 않은 모델을 가리키게 되어, 다음 요청부터 이 현상을 막는다.

업스트림은 2026-09-20에 수정했다(`60028ba`). 수정한 방식도 알아두어야 한다. 이제 **사용자 메시지 맨 처음에 있는 표식만** 인정한다. 작업서는 이 자리에 표식을 두지만 압축 요약은 그렇지 않으므로, 본문 중간에 문법을 인용해도 라우팅을 바꾸지 않는다. 라우터 자체 표기는 `[[ripple: …]]`이며 `[[gpt: …]]`도 계속 인식한다. 접두사 규칙이 일치하더라도 표식의 모델은 그 모델 자체의 규칙이나 그 모델을 단독으로 선언한 제공자에 따라 라우팅한다. 일치한 접두사 규칙의 제공자를 그대로 쓰지 않는다. 따라서 그 제공자가 서비스하지 않는 모델을 표식에 적으면, 제공자에게 보내 400을 받는 대신 라우터가 이유를 명시해 거부한다. 표식으로 정한 라우팅에는 로그 줄에 `(marker)`를 표시한다(`bd39ac3`).

**이제 `providers.*.models`에 모델을 선언하면 에이전트 파일도 만든다.**
`441cb3d`부터 `cli.agentFiles`(기본값 true)를 켜면 라우터가 모델 id마다 `~/.claude/agents/<id>.md`를 쓴다. ingress가 아닌 제공자 중 정확히 하나가 선언한 id만 대상이다. 쓴 파일을 `generated-agents.json`에 기록하고 그 파일만 수정한다. 같은 이름의 수동 작성 에이전트를 우선하므로 `gpt-worker.md`와 `astra-worker.md`는 덮어쓰지 않는다. 이 때문에 `providers.chatgpt.models`를 비워 둘 이유가 하나 더 생겼다. 목록에 모델을 넣으면 불필요한 모델마다 워커가 하나씩 Agent 목록에 생긴다. 선택기 허용 목록은 바로 이를 막으려고 둔 것이다. 표식의 별칭 표는 `aliases`와 모든 에이전트 파일의 이름 → 모델 대응을 합친다. 따라서 워커가 있으면 제공자에 모델을 선언하지 않아도 그 이름을 별칭으로 쓸 수 있다.

**라우터가 처리할 수 없는 비-`claude-*` 모델은 이름과 이유를 명시해 거부한다.**
이것도 `441cb3d`의 변경이다. 전에는 라우팅할 수 없는 id를 일반 `PASS`로 Anthropic에 보냈다. Anthropic이 `404 model: …`로 답해 모델 자체가 작동하지 않는 듯했다. 이제는 라우터에서 이유와 함께 거부한다. 미선언 모델, 두 제공자가 선언한 모델, ingress 제공자만 선언한 모델, 알 수 없거나 대상을 찾을 수 없는 표식 별칭 등이 해당한다. 네이티브 Claude id는 계속 그대로 통과시킨다.

**에이전트 정의는 세션마다 한 번만 읽는다.**
`~/.claude/agents/*.md`의 `model:`을 바꿔도 수정한 세션에는 반영되지 않는다. 계속 이전 값으로 요청한다. 2026-09-19 실측에서는 파일을 이미 `@high`로 바꿨는데도 워커가 폐기한 `gpt-daybreak-blue-high`를 보내 백엔드가 400을 반환했다. frontmatter 수정이 적용됐는지는 새 세션에서 확인한다.

## 에이전트와 Workflow의 결과 받기

**HTML 엔티티 이스케이프는 화면에 표시하는 과정에서 생긴다. 손으로 복원하지 않는다.**
서브에이전트나 Workflow의 결과를 알림이나 결과 텍스트로 받으면 코드의 `<` `>` `&`가 `&lt;` `&gt;` `&amp;`로 바뀐다. 실측으로 두 가지를 바로잡았다.

- **GPT에만 생기는 문제가 아니다.** 같은 Workflow에서 Claude 에이전트가 반환한 값도 `&lt;=`로 바뀌었다. 원인은 모델에 있지 않고 결과를 전달하는 과정에 있다.
- **`journal.jsonl`에는 원문이 있다.** 저널에서 가져온 코드에는 엔티티가 하나도 없었고, 그대로 컴파일해 테스트를 통과했다.

따라서 복원 절차를 만들지 말고 저널에서 읽는다. 위치는 `<transcriptDir>/journal.jsonl`이며, `type == "result"`인 줄의 `result` 필드에 에이전트의 실제 반환값이 있다.

## 워커와 작업하기

**`availableModels`에 슬러그가 없으면 알림 없이 다른 모델로 바꾼다. 문자열이 정확히 일치해야 한다.**
2026-09-18에 `ANTHROPIC_BASE_URL`을 요청 기록기로 지정하고, 나가는 요청의 `model` 필드를 읽어 측정했다. 목록이 `["haiku", "gpt-daybreak-blue@high"]`일 때 `--model gpt-daybreak-blue@high`는 지정한 값 그대로 보냈다. 목록이 `["haiku", "gpt-daybreak-blue"]`이면 같은 플래그를 써도 `claude-opus-5`로 보냈다. stdout과 stderr 어디에도 알리지 않았다. **접미사 없는 id는 `@effort` 형태를 허용하지 않는다.** 따라서 `@high`, `@max`를 포함해 실제로 쓰는 형태를 모두 목록에 적어야 한다. anthropics/claude-code#95324로 보고했다. 워커의 결과물을 Claude가 쓴 듯하면 허용 목록부터 확인한다.

**선택기 항목의 `behavesAs`는 미인식 모델 경고를 없앤다. 존재하지 않는 대상은 무시한다.**
`behavesAs: "claude-opus-5"`를 쓰자 `isn't described by this version's model catalog` 문단이 사라졌다. 같은 자리에 `claude-nonexistent-9`를 쓰자 그 값을 무시했고 문단이 다시 나타났다(2026-09-18 실측).

**`[1m]`은 허용 목록 검사와 요청 전송 전에 제거한다.**
`--model 'gpt-6-astra@high[1m]'`로 호출하면 `gpt-6-astra@high`를 전송하며, `[1m]`이 없는 허용 목록 항목과 일치한다. 라우터를 바꾸거나 컴퓨터 전체에 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`를 설정하지 않고도, 클라이언트에서 Claude Code에 윈도우가 1M임을 알리는 방법이다. `behavesAs`와 함께 쓰면 어느 윈도우가 우선하는지는 측정하지 않았다.

**워커의 자기 보고와 결과물은 별개다(실측 사례).**
혼합 세션을 검증할 때 워커는 파일에 올바른 결과(`ykseulb`)를 쓰고 보고 문장에는 오탈자(`ykseulba`)를 냈다. 항상 결과물을 직접 열어 판단한다. 채팅 보고만으로 검증을 대신하지 않는다.

**Windows에서 셸을 허용할 때는 셸 도구 둘 다 허용한다.**
Claude Code에는 `Bash`와 `PowerShell`이 있다. `Bash`만 허용한 워커가 `PowerShell`을 고르면 자동으로 거부되며 승인을 요청할 수도 없다. 2026-09-12 실측에서 ASTRA 워커가 PowerShell을 골랐고, cargo와 pnpm 검증 명령은 모두 `requires approval`을 반환했다. 워커는 하나도 검증하지 못한 코드를 제출했다. 두 이름을 모두 허용하거나 둘 다 허용하지 않는다.

**워커는 스스로 서브에이전트와 워크트리를 만든다.**
자기 판단으로 서브에이전트를 실행하고 별도 워크트리에 결과물을 만들며, 다른 세션에 메시지까지 보낸다(실측). 완료 보고만 믿지 말고 작업 트리를 직접 확인한다. 메인 트리 밖에 만든 결과물은 복사해 온다. 작업서에 결과물을 쓸 절대경로를 명시하면 다른 위치에 쓸 일이 줄어든다.

**Claude는 항상 검증 명령을 다시 실행한다.**
워커가 통과했다고 보고해도 Claude가 직접 포맷, 린트와 테스트를 실행한다. 실제로 워커의 결과물에서 `cargo fmt --check`가 실패해 커밋 전에 `cargo fmt --all`이 필요했다. 컴파일 성공 여부와 보고의 정직성은 별개다.

**구현과 감사는 따로 실행한다.**
완성된 코어를 새로 실행한 읽기 전용 워커에게 맡기자 실제 결함을 찾았다. 파일을 새로 만드는 코드에서 id 충돌 검사와 저장이 같은 잠금 안에 있지 않아, 동시에 파일을 만들면 경쟁 조건이 생겼다. 같은 모델이라도 새 맥락에서 다시 보면 다른 문제를 찾는다. 구현과 감사를 서로 다른 워커에게 맡기면 비용을 아낄 수 있다.

**워커가 문서를 확인하게 한다.**
허용 도구에 WebSearch와 WebFetch를 넣으면 크레이트 API를 추측해 지어내는 일이 줄어든다. 확인하지 못한 것을 지어내게 두는 것보다 문서를 확인하게 하는 편이 싸다. 셸을 허용할지는 별도로 신중히 정한다. 감독 없이 쓰는 셸이기 때문이다.

**워커의 WebSearch는 워커 모델로 실행하지 않으며 ChatGPT 쿼터도 쓰지 않는다.**
Claude Code는 세션 모델과 관계없이 모든 웹 검색을 고정된 소형 모델의 별도 요청으로 Anthropic에 직접 보낸다. 따라서 라우터를 거치는 워커에서도 검색은 작동하지만 Claude에 과금한다. 검색 질의를 작성하고 읽는 모델도 실제 작업을 하는 모델과 다르다. 결과에는 제목, URL과 검색 모델이 쓴 설명만 남는다. CLI가 검색 결과의 발췌문을 버린다(2026-09-17 업스트림 실측). API의 정확한 문구가 필요하면 URL을 지정하고, 처음부터 끝까지 로컬에서 처리하는 WebFetch를 쓰게 한다.

**claude.ai 커넥터의 도구는 늦게 나타난다.**
커넥터는 불러오지만, 연결을 마친 뒤에야 그 도구를 목록에 추가한다. 그때까지 몇 턴이 걸리기도 한다. 한 턴짜리 확인에서는 도구가 없다고 보고했고, 네 턴짜리 실행에서는 그 도구를 썼다. 워커에게 먼저 할 일을 주거나 작업서에 도구 이름을 적고 다시 시도하게 한다.

## 실행 환경

**지침 블록의 U+FFFD 깨짐은 2.1.278에서 재현되지 않았다.**
`anthropics/claude-code#93848`은 프롬프트에 넣은 `CLAUDE.md`의 멀티바이트 문자 하나가 U+FFFD 세 개로 바뀌는 결함이다. 이 때문에 프롬프트 접두사가 달라져 대화 전체의 캐시를 쓰지 못했다. 2.1.258에서는 요청 17개 중 3개에서 확인했다. 2026-09-20에 같은 기록 방식으로 2.1.278을 다시 측정했다. 요청 29개를 기록했고, 그중 27개에 해당 블록이 있었다. 27개 모두 시드 해시가 같았으며 본문 6.6 MB에서 `EF BF BD` 바이트는 하나도 없었다. 예전에 깨지던 문자는 당시 블록의 바이트 오프셋 7,982에 있었고 지금은 7,885에 있다. 따라서 그 문자가 있는 위치를 27번 모두 오류 없이 처리했다. 이전 발생률대로라면 27번 중 한 번도 발생하지 않을 확률은 0.5%다. 27번 모두 발생하지 않았다는 관측에 따른 발생률 상한은 10.5%다. 수정됐다고 단정하지 말고, 시도할 때마다 재현할 수 있는 상태는 아니라고 본다. 다음에 세션의 캐시 적중률이 이유 없이 낮아질 때를 대비해 기록기를 준비해 둔다. 각 요청 본문을 저장하고 전달하는 로컬 서버에 `ANTHROPIC_BASE_URL`을 지정하면 된다.

**자동 모드 분류기는 `--dangerously-skip-permissions`를 차단한다.**
부모 Claude 세션 안에서 자식 `claude`를 위험 모드로 실행하려는 시도를 거부한다.

**cmd에서는 따옴표 안의 경로가 역슬래시로 끝나면 닫는 따옴표를 이스케이프한다.**
`/Fo:"...\obj\"`처럼 따옴표로 감싼 경로가 역슬래시로 끝나면 닫는 따옴표를 이스케이프해 명령줄 전체를 잘못 해석한다. cl은 `D8003 missing source filename` 오류로 종료한다. 해당 디렉터리로 이동해 상대경로를 쓰거나 마지막 역슬래시를 뺀다.

**Bash 도구의 heredoc은 내용에 작은따옴표가 있으면 실패한다.**
`&'static` 같은 조각이나 일반적인 영어 아포스트로피가 있는 heredoc을 쓰면 셸의 따옴표 해석이 어긋나 `unexpected EOF while looking for matching`으로 종료한다. 이런 파일은 Write 도구로 쓴다. Rust 수명 표기, PowerShell 리터럴 문자열, 일반 글 모두 해당한다.

**Bash 도구의 cwd는 믿지 않는다.**
이전 호출의 `cd`가 유지될 때도 있고 도구가 프로젝트 루트로 되돌릴 때도 있다. 어느 쪽이든 경로는 항상 절대경로로 쓴다.

## 배포

**토이 프로젝트(공개용)와 스킬(내부 인프라)을 같은 브랜치에 커밋하지 않는다.**
내부 GPT 도구가 공개 저장소에 섞이면 자동 모드 분류기가 push를 차단한다.

**create-tauri-app은 Windows 사용자명을 식별자에 넣는다.**
식별자가 `com.<Korean username>.…` 형태가 되며, `generate_context!`가 비-ASCII 식별자를 거부하기도 한다. ASCII reverse-DNS 이름으로 고친다.
